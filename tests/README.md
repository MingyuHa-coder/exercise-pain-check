# 자동 테스트

앱을 실제 브라우저(Chromium)로 열어 검사한다. 코드를 고친 뒤 매번 다시 실행한다.

## 준비 (처음 한 번)

```bash
npm install --no-save playwright
npx playwright install chromium
```

## 실행

```bash
node tests/run-tests.js              # 전체 (화면 흐름 포함, 몇 분 걸림)
node tests/run-tests.js --quick      # 13개 주제 화면 클릭 흐름만 생략
node tests/run-tests.js --only review   # 전문가 검토 표시 테스트만
node tests/run-tests.js --app <폴더>    # 다른 폴더의 앱 검사 (예전 버전과 비교할 때)
```

실패가 하나라도 있으면 종료 코드가 1이다. 마지막 줄에 `합계 PASS n / FAIL n`과 실패한 항목이 나온다.

## 무엇을 검사하나

| 묶음 | 내용 |
| --- | --- |
| 검토 표시 구조 | 검토 완료 뒤 더 최근의 "수정 필요"·"검토 중" 기록이 오면 완료 표시가 사라지는지, 일부 항목 검토, 판단 규칙 지문(referOnly·답 값·미리 채우는 답·finish·has·새 판단 속성·위험 신호 단계)이 바뀌면 재확인으로 바뀌는지, 문구만 바꾸면 규칙 검토가 유지되는지, 실제 검토 기록이 0개인지 |
| 판단 결과 | 13개 주제 예시 답변 결과, 무작위 답변 52,000개에서 모순(변수 없는 조정, 진료 먼저 변수와 조정 동시 표시, 0점 변수 표시) 없음, 답이 모호할 때 안내만 |
| 안전 | 위험 신호 75개 모두 진료 안내 화면에서 멈추고 조정으로 넘어가지 않음 |
| 화면 문구 | 숨긴 질환명·진단 문장이 보이지 않음(근거 자료 목록 제외), "2주" 없음, 전문가 화면 분리 |
| 저장 | 예전 형식 이전, 첫 저장 전 안내, 삭제, 저장·삭제 실패 안내, 현지 날짜(자정 전후, 한국 오전 9시 전후) |
| 화면 흐름 | 부위 → 운동 → 위험 신호 → 질문 → 결과 → 기록 → 전문가 화면을 13개 주제 모두 클릭으로 진행 |

테스트는 페이지 안에서 검토 기록이나 콘텐츠를 잠깐 바꿨다가 되돌린다. 저장소 파일은 바꾸지 않는다.
