# 데이터 저장과 개인정보 (콘텐츠 버전 8 기준)

이 문서는 앱이 어떤 정보를 어디에 저장하는지 정리한 내부 자료다. 법률 해석을 확정하는 문서가 아니며, 개인정보 보호법 적용 여부와 필요한 고지 수준은 별도 법률 검토가 필요하다.

## 1. 지금 구조: 서버 없음, 브라우저에만 저장

- 앱은 GitHub Pages에 올린 정적 웹페이지다. 회원가입, 로그인, 서버 저장, 분석 도구가 없다.
- 모든 계산은 사용자 브라우저 안에서 한다.
- AI 서비스를 포함한 어떤 외부 서비스에도 사용자의 답변이나 기록을 보내지 않는다.

| 정보 | 저장 위치 | 저장 키 | 성격 | 보관 |
| --- | --- | --- | --- | --- |
| 설명 방식 (쉬운 말/의학 용어) | 브라우저 localStorage | `epc.settings` | 일반 설정 | 사용자가 지울 때까지 |
| 기록 저장 안내를 확인한 날짜 | 브라우저 localStorage | `epc.settings` 안 `logNotice` | 일반 설정 | 사용자가 지울 때까지 |
| 조정별 결과 기록 (주제·조정 이름, 날짜, 덜/같음/더 아픔, 저장 시각) | 브라우저 localStorage | `epc.healthlog` | **건강 관련 정보** (어느 운동·부위가 아팠는지 추정 가능) | 보유 기간 **미정** |
| 위험 신호·상황 질문 답변 | 화면 메모리만 | (없음) | 건강 관련 정보 | 저장 안 함. 새로고침하면 사라짐 |
| 전문가에게 보여줄 요약 | 사용자가 누를 때만 클립보드로 복사 | (없음) | 건강 관련 정보 | 앱이 보관하지 않음 |

### 데이터 형식

```js
// epc.settings
{ schema: 1, level: "easy" | "pro", logNotice: { accepted: true, date: "ISO 날짜" } | null }

// epc.healthlog  (기록이 하나도 없으면 키 자체가 없다)
{ schema: 1, createdAt: "ISO", updatedAt: "ISO", migratedFrom?: "bench-shoulder-log",
  entries: { "주제id:조정id": [ { d: "YYYY-MM-DD", v: "less" | "same" | "more", savedAt: "ISO" | null } ] } }
```

- `schema`: 데이터 형식 버전. 형식을 바꾸면 올리고, 옛 형식을 옮기는 코드를 둔다.
- 하루에 같은 조정은 한 번만 남는다(같은 날 다시 누르면 덮어씀).
- v7까지의 저장 키(`painLevel`, `bench-shoulder-log`)는 v8을 처음 열 때 새 형식으로 옮기고 지운다. 옮긴 기록은 `savedAt`이 `null`이다.

## 2. 저장 전 안내와 삭제

- **저장 전 안내:** 결과 기록 버튼을 처음 누르면 저장하기 전에 안내를 보여준다. 무엇이 저장되는지, 이 기기에만 저장되는지, 같은 기기 사용자가 볼 수 있다는 점, 보관 기간이 정해지지 않았다는 점, 지우는 방법을 알린다. "알겠어요, 저장할게요"를 눌러야 저장하고, "저장하지 않기"를 누르면 아무것도 저장하지 않는다.
- **삭제:** 시작 화면의 "이 기기에 저장된 기록" 카드와 결과 화면의 조정 목록 아래에 "내 기록 모두 지우기"가 있다. 누르면 `epc.healthlog`와 옛 키를 지운다. 설정(`epc.settings`)은 건강 기록이 아니라서 남는다.
- 브라우저의 사이트 데이터 삭제로도 모두 지워진다.

## 3. 아직 정하지 않은 것

- **보유 기간:** 앱이 임의로 정하지 않았다. 법률 검토나 운영 정책으로 정해지면 `createdAt`과 `savedAt`을 이용해 자동 삭제를 넣을 수 있다.
- **외부 요청:** Google Fonts에서 글꼴을 불러와서 접속 정보(IP 등)가 Google에 전달된다. 건강 정보는 포함되지 않는다. 글꼴 파일을 저장소에 직접 넣으면 없앨 수 있다(권장 사항).
- **호스팅 기록:** GitHub Pages는 접속 기록을 남길 수 있다. 앱이 통제하지 않는 부분이다.

## 4. 서버·계정 기능으로 확장할 때 필요한 것 (지금은 만들지 않음)

서버 저장이나 회원가입을 도입하면 아래 설계와 법률 검토가 먼저 필요하다.

1. **별도 동의:** 통증 위치·증상·결과 기록은 개인정보 보호법상 민감정보(건강)에 해당할 수 있다. 일반 개인정보 동의와 분리한 별도 동의가 필요한지 확인한다.
2. **분리 보관:** 계정 정보(이메일 등)와 건강 기록을 다른 저장소·테이블에 나눠 두고, 연결은 내부 식별자로만 한다.
3. **최소 수집:** 지금처럼 답변 원문은 저장하지 않는 방향을 유지한다. 저장이 꼭 필요한 항목만 정한다.
4. **보안:** 전송 구간 암호화(HTTPS), 저장 데이터 암호화, 접근 권한 관리, 접근 기록.
5. **보유 기간과 삭제:** 보유 기간을 정해 고지하고, 기간이 지나면 자동 삭제한다. 사용자가 언제든 전부 지울 수 있게 한다.
6. **이전:** 브라우저의 `epc.healthlog`를 계정으로 옮길 때는 사용자 동의를 받은 뒤에만 옮긴다(`schema` 버전으로 형식 확인).
7. **AI 기능:** AI 외부 서비스에 건강 기록을 보내지 않는다. AI를 쓰더라도 승인된 콘텐츠 검색에 한정하고, 개인 기록은 보내지 않는다.
8. **고지 문서:** 개인정보 처리방침, 이용약관, 수집 목적·항목·보유 기간 안내.
